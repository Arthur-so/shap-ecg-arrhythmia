1 Fluxo conceitual do trabalho

Da matéria-prima (sinais de ECG) até a resposta científica, em três grandes fases.

🫀 Pré-processamento
  1. Importar a base CPSC20186.877 ECGs · 12 derivações · 500 Hz
  2. Ler os rótulos9 classes diagnósticas, multi-rótulo
  3. Padronizar o comprimentotruncar/preencher até 15.000 amostras (30 s)
  4. Normalizar (z-score)média/desvio por derivação
  5. Dividir os dadosestratificado 70% / 20% / 10%
▶
🧠 Processamento
  1. Treinar a ResNet34 1DAdam · BCE ponderada · early stopping (F1-macro)
  2. Medir desempenho por classeF1-score de cada condição
  3. Gerar explicações SHAPGradientSHAP nos acertos do teste, por classe
  4. Mapas de atribuição15.000 × 12 por amostra
▶
📊 Análise
  1. Medir qualidade das explicaçõesQuantus: Faithfulness (6) + Robustness (7)
  2. Agregar por classevalor médio de cada métrica por condição
  3. Comparar com o F1correlação qualidade × desempenho por classe
  4. Interpretara qualidade acompanha ou se dissocia do desempenho?

2 Status atual da implementação

O que já existe do fluxo acima e como está sendo feito.

EtapaStatusComo está sendo feito
Importar base + rótulos Feito A base é lida dos registros WFDB (12 derivações). Os rótulos são detectados automaticamente em dois formatos: REFERENCE.csv (códigos 1–9) ou, no dataset do Kaggle, os códigos SNOMED gravados no campo #Dx: de cada cabeçalho .hea — mapeados para as 9 classes. Validado com um cabeçalho real.
Padronização + z-score Feito Cada sinal é truncado/preenchido com zeros até 15.000 amostras e normalizado por z-score por derivação. Transformações testadas (padding vira zero; média≈0 e desvio≈1 por canal).
Divisão dos dados Feito Split estratificado multi-rótulo 70/20/10 com semente fixa. Testado: bate exatamente as frações e preserva a proporção das classes raras (BRE, STE) nas três partições.
Modelo ResNet34 1D Feito Arquitetura de 34 camadas ([3,4,6,3] blocos residuais), saída de 9 logits. Validado forward e backward no formato real (12 × 15.000), ~7,2 M de parâmetros.
Treino do modelo Implementado — não treinado Loop com Adam, BCE ponderada pela frequência das classes e early stopping por F1-macro; salva checkpoint e F1 por classe. Rodou ponta a ponta com dados sintéticos. Falta o treino real (exige GPU do Kaggle, hoje bloqueada por verificação de conta).
Explicações GradientSHAP Implementado — não executado nos dados Via Captum, aplicado só aos acertos do teste, por classe predita, com baselines do treino. Validado end-to-end gerando mapas 12 × 15.000. Falta rodar sobre o modelo treinado real.
Métricas Quantus Implementado — não executado As 13 métricas (6 Faithfulness + 7 Robustness) estão configuradas e agregam por classe, com fallback caso alguma falhe. Falta executar sobre as atribuições reais.
Análise de correlação Pendente O cruzamento métricas × F1 por classe já é gerado em CSV pelo código; a análise/discussão em si depende dos resultados reais das etapas anteriores.
Feito = implementado e validado Implementado, mas ainda não executado em dados reais Pendente

3 Pipeline de execução (como roda de verdade)

Onde cada peça vive e como uma execução acontece de ponta a ponta.

💻 Local (PC)
Edição do código
Lógica em src/ e o notebook runner são editados aqui.
▶
🐙 GitHub
Versionamento
git push envia o código. Só código e resultados agregados (sem dados/pesos).
▶
🚀 Script run.sh
Dispara + acompanha
Publica o notebook no Kaggle e fica exibindo status e log ao vivo.
▶
📓 Notebook (Kaggle)
Runner na GPU
Faz git pull do código + usa o dataset montado, e executa preprocess → treino → SHAP → Quantus.
▶
📦 Saída
Resultados
F1 por classe, métricas Quantus e tabelas em results/; logs voltam ao terminal.
🔁 Nada é ao vivo/automático: mudanças em src/ só valem quando o notebook roda de novo (ele começa com git pull). O dataset CPSC2018 é anexado ao notebook e montado em /kaggle/input/…, sem download manual.
